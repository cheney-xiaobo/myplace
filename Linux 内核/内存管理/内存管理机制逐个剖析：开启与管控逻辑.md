## 0. 阅读方法

每个机制按同一模板展开：

1. **开启前置**：Kconfig、平台依赖、模块/用户态依赖。
2. **开关与参数**：真实路径、默认值、取值范围。
3. **管控逻辑**：触发条件 → 决策 → 执行 → 退出/回退，落到源码行号。
4. **判据**：哪个计数器/文件能证明它真的在跑。
5. **互斥与坑**：和谁冲突、顺序要求、常见误判。

## 1. NUMA balancing（自动页迁移）

### 开启前置
- `CONFIG_NUMA_BALANCING=y`、`CONFIG_NUMA_BALANCING_DEFAULT_ENABLED=y`（`arch/x86/configs/openeuler_defconfig:185-186`）
- 只在多 NUMA 节点时启用（`mm/mempolicy.c:3414-3428`）；单节点机器上打开也不会有动作。

### 开关与参数
- 模式：`kernel.numa_balancing` = 0/1/2/3（`kernel/sched/core.c:4483-4503`、`kernel/sched/core.c:4644-4651`）
  - bit0 = NORMAL（普通 NUMA 平衡），bit1 = MEMORY_TIERING（分层），定义在 `include/linux/sched/sysctl.h:22-27`
- 扫描参数（`kernel/sched/fair.c:1779-1786`）：
  - `scan_period_min` 默认 1000 ms、`scan_period_max` 默认 60000 ms
  - `scan_size` 默认 256 MB、`scan_delay` 默认 1000 ms
- 每次 `task_numa_work` 扫描的页数 = `scan_size << (20 - PAGE_SHIFT)`（`kernel/sched/fair.c:1840`），扫描窗口按 vma 轮转。

### 管控逻辑
1. **触发**：`task_tick_numa()` 在 tick 中给任务挂 callback（`kernel/sched/fair.c:3867`、`kernel/sched/fair.c:15286`）。
2. **扫描**：`task_numa_work`（`kernel/sched/fair.c:3614`）按窗口把 PTE 标成 PROT_NONE，制造 hint fault。
3. **决策**：`task_numa_placement`（`kernel/sched/fair.c:3213`）根据 fault 分布计算任务「偏好节点」，若当前节点不是首选且迁移收益足够，就迁移。
4. **退避**：扫描周期从 min 逐步翻倍到 max（`kernel/sched/fair.c:2228`），无收益时变慢。

### 判据
- `grep numa_pte_updates /proc/vmstat`、`grep numa_hint_faults /proc/vmstat`
- `numastat -p <pid>`、`/proc/<pid>/numa_maps`

### 互斥与坑
- `kernel.numa_balancing=2` 只开分层位，**不会**建立 tier 拓扑；需要 §7 的 memory tiers。
- 扫描本身有开销；大内存任务在 `scan_period_max` 下可能「照顾不到」冷区。

## 2. MGLRU（多代 LRU）

### 开启前置
- `CONFIG_LRU_GEN=y`（x86-dc:1235），但 `CONFIG_LRU_GEN_ENABLED` 未设置（x86-dc:1236；arm64-dc:1269）
- 默认静态键为 false（`mm/vmscan.c:2631-2636`）→ 默认走经典双链 LRU

### 开关与参数
```bash
cat /sys/kernel/mm/lru_gen/enabled      # 默认 0x0000
echo y > /sys/kernel/mm/lru_gen/enabled # 全开（0x0007）
echo 5 > /sys/kernel/mm/lru_gen/enabled # 只开位 0 和 2
```
- `enabled` 位含义见 `Documentation/admin-guide/mm/multigen_lru.rst:27-31`
- `min_ttl_ms`（`mm/vmscan.c:5182-5201`）：保护最近 N 毫秒的工作集，默认 0（不保护）
- 运行时切换入口在 `mm/vmscan.c:5247-5251`

### 管控逻辑
1. **分代**：每个 lruvec/type 维护 `MAX_NR_GENS` 代（`mm/vmscan.c:2663`），新页进最新代，引用位由 `sort_folio`（`mm/vmscan.c:4318`）分流。
2. **老化决策**：`should_run_aging`（`mm/vmscan.c:4685`）统计 old/young 占比：
   - 若 young 超过 1/(MIN_NR_GENS+1) → 认为还有热页，继续老化；
   - 若 old 低于 1/(MIN_NR_GENS+1) → 认为代分布过旧，也老化；
   - 否则直接进入回收（`mm/vmscan.c:4720-4746`）。
3. **回收量**：`get_nr_to_scan = total >> priority`（`mm/vmscan.c:4730`），`evict_folios`（`mm/vmscan.c:4596`）从最老代扫描并回收。
4. **保护**：`min_ttl_ms` 内的页不会被回收（`mm/vmscan.c:4010-4020`）。

### 判据
- `/sys/kernel/mm/lru_gen/enabled` 非 0；
- `/sys/kernel/debug/lru_gen`（debugfs）里的代统计；
- kswapd CPU 与 `pgscan` 变化。

### 互斥与坑
- **MGLRU 与 zram_reclaim 互斥**：`lru_gen_enabled()` 为真时 zram_reclaim 直接返回 false（`mm/zram_reclaim.c:209-211`）。
- MGLRU 与 DAMON_LRU_SORT 都改 LRU 行为，叠加前要测。

## 3. zswap（前端压缩）

### 开启前置
- `CONFIG_ZSWAP=y`，但 `CONFIG_ZSWAP_DEFAULT_ON` 未设置（x86-dc:1110-1111）
- 默认压缩器 lzo、zpool zsmalloc（x86-dc:1114-1122）

### 开关与参数
```bash
echo 1 > /sys/module/zswap/parameters/enabled
cat /sys/module/zswap/parameters/max_pool_percent   # 默认 20
cat /sys/module/zswap/parameters/accept_threshold_percent
cat /sys/module/zswap/parameters/same_filled_pages_enabled
cat /sys/module/zswap/parameters/exclusive_loads
```
- 参数定义：`mm/zswap.c:96`（enabled）、`:121-126`（max_pool / accept_threshold）、`:134-144`（same_filled / exclusive_loads）

### 管控逻辑
1. **入口**：swap-out 时 `zswap_store`（`mm/zswap.c:1270-1300`）先检查：
   - `zswap_enabled` 是否开；
   - memcg 的 `obj_cgroup_may_zswap()` 是否允许；
   - `zswap_is_full()`（`mm/zswap.c:268`，占用 > `totalram * max_pool_percent / 100`）→ 触发 `shrink`。
2. **回收**：`queue_work(shrink_wq, &pool->shrink_work)`（`mm/zswap.c:1427`）→ `shrink_worker`（`mm/zswap.c:722`）从 LRU 取 entry → `zswap_writeback_entry`（`mm/zswap.c:1088`）回写到真实 swap 设备。
3. **回退阈值**：池满后，只有占用降到 `accept_threshold_percent` 以下才继续接收新页（`mm/zswap.c:126`）。
4. **读回**：`zswap_load`（`mm/zswap.c:1432`），`exclusive_loads` 控制读回后是否从 zswap 删除。
5. **同值页**：`same_filled_pages_enabled` 让相同内容的页共享一个 entry。

### 判据
- `/proc/vmstat` 的 `zswap_*`（store/load/reject/writeback）
- `/sys/kernel/debug/zswap/*`（pool 大小、命中）

### 互斥与坑
- zswap 是「swap 设备前面的压缩层」；和 zram 叠加时是**两次压缩**（zswap→zram），CPU 翻倍、收益递减，必须先测。
- 本树注释明确：zswap 回收还**不是 cgroup-aware**（`mm/zswap.c:1273-1278`），memcg 限额下会按全局 LRU 推出 entry。

## 4. PSI（压力反馈）

### 开启前置
- `CONFIG_PSI=y`，但 `CONFIG_PSI_DEFAULT_DISABLED=y`（x86-dc:141-142）
- 默认静态键 disabled（`kernel/sched/psi.c:144-148`）；启动参数 `psi=1`（`Documentation/admin-guide/kernel-parameters.txt:4831`）

### 开关与参数
```bash
cat /proc/pressure/memory
cat /sys/fs/cgroup/<cg>/memory.pressure
```
- 输出格式：`some avg10=... avg60=... avg300=... total=...`（`kernel/sched/psi.c:1546`）

### 管控逻辑
1. **采样**：PSI 跟踪处于 D 状态（等内存/IO）的任务时间，按 cgroup 聚合。
2. **聚合**：`PSI_AVGS`（滑动平均）用于普通读取；`PSI_POLL` 用于特权触发（`kernel/sched/psi.c:1622`）。
3. **触发**：向 `memory.pressure` 写入 `some <stall_us> <window_us>` → `psi_trigger_create`（`kernel/sched/psi.c:1557`）；用户态 `poll()` 该 fd，超阈值被唤醒；`psi_trigger_destroy`（`kernel/sched/psi.c:1659`）释放。
4. **语义**：PSI 只**观测**，不直接触发内核回收；它是策略层的反馈信号（DAMON/用户态 daemon/调度器可消费）。

### 判据
- `/proc/pressure/memory` 存在且 total 增长；
- 触发 fd 的 poll 返回。

### 互斥与坑
- 默认关闭时 `/proc/pressure` 不存在，很多监控脚本会误判为「内核不支持」。

## 5. memory.reclaim / memory.high（memcg 主动回收与节流）

### 开启前置
- `CONFIG_MEMCG=y`（x86-dc:190）；cgroup v2 挂载

### 开关与参数
```bash
echo "100M" > /sys/fs/cgroup/<cg>/memory.reclaim
echo "100M anon" > /sys/fs/cgroup/<cg>/memory.reclaim   # 只回收匿名页
echo "100M file" > /sys/fs/cgroup/<cg>/memory.reclaim   # 只回收文件页
echo 512M > /sys/fs/cgroup/<cg>/memory.high
```
- 语法解析在 `mm/memcontrol.c:8194-8240`（字节数 + `anon`/`file` 类型）
- `memory.high` 写入在 `mm/memcontrol.c:7968`（v2）、`:6130`（v1）

### 管控逻辑
1. **memory.reclaim**：`memory_reclaim`（`mm/memcontrol.c:8238-8280`）循环调用 `try_to_free_mem_cgroup_pages`，每批最多 `SWAP_CLUSTER_MAX`，带 `MAX_RECLAIM_RETRIES` 重试；最后一轮先 `lru_add_drain_all()` 再试；无进展返回 `-EAGAIN`。
2. **memory.high**：charge 超过 high → `schedule_work(&memcg->high_work)`（`mm/memcontrol.c:2652` 附近）→ `high_work_func`（`mm/memcontrol.c:2622`）→ `reclaim_high(memcg, MEMCG_CHARGE_BATCH)`；若开了 MEMCG_QOS 且 `high_async_reclaim` 为真，走 `async_reclaim_high`。
3. **节流**：超限越多，睡眠时间越长，上限 `MEMCG_MAX_HIGH_DELAY_JIFFIES`（2 秒）（`mm/memcontrol.c:2638`）。
4. **memory.max**：`memory_max_write`（`mm/memcontrol.c:8020`）超限触发 OOM。

### 判据
- `memory.stat` 的 `pgscan`/`pgsteal` 增长；
- `memory.events` 的 `high`/`max` 计数。

### 互斥与坑
- `memory.reclaim` 是**一次性**接口，不会持续后台回收；持续压力靠 `memory.high` + 用户态循环。
- `file` 类型回收不掉脏页，脏页会先回写，时延不可控。

## 6. demotion / memory tiers（冷页下沉）

### 开启前置
- tier 拓扑先建立（HMAT/CXL 或手动）；`numa_demotion_enabled` 默认 **false**（`mm/memory-tiers.c:937`）
- NUMA balancing 的 tiering 位（`kernel.numa_balancing=2`）只决定「promote 侧」，demotion 侧由 `demotion_enabled` 单独控制。

### 开关与参数
```bash
cat /sys/kernel/mm/numa/demotion_enabled
echo true > /sys/kernel/mm/numa/demotion_enabled
grep pgdemote_ /proc/vmstat
```
- sysfs 属性在 `mm/memory-tiers.c:961-965`

### 管控逻辑
1. **准入**：`can_demote(nid, sc)`（`mm/vmscan.c:314-320`）= `numa_demotion_enabled` 且 `next_demotion_node(nid) != NUMA_NO_NODE`。
2. **目标节点**：`next_demotion_node`（`mm/memory-tiers.c:329`）查 `node_demotion[]` 表，由 tier 拓扑（距离/带宽）生成。
3. **执行**：`shrink_node` 里 `do_demote_pass = can_demote(...)`（`mm/vmscan.c:1050`），回收时把选中页放进 `demote_folios`（`mm/vmscan.c:1222`）→ `demote_folio_list`（`mm/vmscan.c:978`）→ `migrate_pages`（`mm/vmscan.c:1006`）。
4. **回退**：迁移失败的页留在 LRU 继续走正常回收（`mm/vmscan.c:1521-1522`）。
5. **分配**：`alloc_demote_folio`（`mm/vmscan.c:943`）负责目标节点的页分配，失败即回退。

### 判据
- `pgdemote_kswapd`/`pgdemote_direct`/`pgdemote_khugepaged` 增长（`mm/vmstat.c:1250-1252`）
- 各 node 的 `MemFree`/`FilePages` 变化

### 互斥与坑
- 没有 tier 拓扑时 `node_demotion` 为空，开了也不生效。
- 迁移有 CPU 与锁开销；高频 demotion 会拖慢回收路径。

## 7. DAMON

### 开启前置
- `CONFIG_DAMON=y` + `VADDR`/`PADDR`/`SYSFS`/`RECLAIM`/`LRU_SORT`（x86-dc:1253-1259）
- 需要用户态配置（sysfs）或加载 module 版；ARM64 可用硬件采样（arm64-dc:1287、`mm/Kconfig:1519-1527`）

### 开关与参数
- sysfs 结构：`/sys/kernel/mm/damon/admin/kdamonds/<n>/...`，关键参数：
  - `nr_regions` 默认 10-1000（`mm/damon/sysfs.c:581`）
  - scheme 的 `access_pattern`（min/max age）、`quotas`（time/space）、`watermarks`、`action`
- module 版 `damon_reclaim`：`min_age` 默认 120000000 us（120 秒）（`mm/damon/reclaim.c:50`）、quota 在 `mm/damon/reclaim.c:53-63`

### 管控逻辑
1. **采样**：按采样间隔读访问位，统计每个 region 的访问频率；region 数在 min/max 间自适应分裂/合并。
2. **决策**：scheme 用 `access_pattern` 过滤（如 age ≥ min_age），再用 quota/watermark 限速，决定命中区域。
3. **执行**：action 可为 stat / pageout / migrate_hot / migrate_cold / lru_priority / lru_sort。
4. **回收版**：`damon_reclaim` 对「age ≥ min_age 且未超 quota」的区域执行 pageout（`mm/damon/reclaim.c:126-139`）。
5. **LRU 版**：`damon_lru_sort` 按访问频率把页调到 active/inactive 链。

### 判据
- `/sys/kernel/mm/damon/admin/kdamonds/0/state` = `on`
- `damon_reclaim` 的 `reclaim_tried_regions`/`reclaimed_regions` 统计
- `pgscan`/`pgsteal` 与 `pgdemote_*` 变化

### 互斥与坑
- DAMON 是「先采样、后动作」，采样间隔决定反应速度；高采样率有 CPU 开销。
- `DAMON_LRU_SORT` 与 MGLRU 都改 LRU 行为，叠加要单独验证。

## 8. etmem（openEuler 分层）

### 开启前置
- `CONFIG_ETMEM=y` + `etmem_scan`/`etmem_swap` 模块（x86-dc:1244-1246）
- 需要用户态 etmemd 驱动（`mm/Kconfig:1498-1504` 的说明）

### 开关与参数
```bash
cat /sys/kernel/mm/swap/kernel_swap_enable    # 默认 true
lsmod | grep etmem
```
- 属性注册在 `mm/swap_state.c:927-941`（`swap_attrs` 组挂在 `/sys/kernel/mm/swap/`）
- `kernel_swap_enable` 控制「内核是否允许 swap」：vmscan 在 `mm/vmscan.c:2417`、`mm/vmscan.c:2695` 用它做 gate

### 管控逻辑
1. **扫描**：`etmem_scan.ko` 周期扫描目标进程 vma 的页表，利用 `get_page_from_vaddr`（导出符号，`mm/etmem.c:99`）读取页状态。
2. **判定**：用户态 etmemd 按阈值（冷页比例、目标水位）决定哪些页可换出。
3. **执行**：`etmem_swap.ko` 调 `add_page_for_swap`（`mm/etmem.c:73`）把页加入 swapcache，`do_swapcache_reclaim`（`mm/etmem.c:272`）触发回收。
4. **回退**：`kernel_swap_enable=false` 时 vmscan 不做 swap，etmem 只能走文件回收。

### 判据
- `/sys/kernel/mm/swap/kernel_swap_enable`
- etmemd 日志 + 目标进程 `VmRSS`/`VmSwap`
- `/proc/vmstat` 的 `pswpout`

### 互斥与坑
- `kernel_swap_enable` 是**全局**开关，关掉会影响所有进程的 swap，不只是 etmem。
- etmem 依赖用户态 daemon，内核侧只提供扫描/换出原语。

## 9. zram_reclaim（openEuler，ARM64 限定）

### 开启前置
- `CONFIG_ZRAM_RECLAIM`（`mm/Kconfig:64-80`）、`ARM64 && MEMCG && SWAP`；arm64-dc:1152
- 仅特定 HiSilicon CPU 注册 `memory.zram_reclaim`（`Documentation/admin-guide/mm/zram_reclaim.rst:42-55`）
- MGLRU 必须**未生效**（`Documentation/admin-guide/mm/zram_reclaim.rst:25-27`）

### 开关与参数
```bash
echo "1 30" > /sys/fs/cgroup/<cg>/memory.zram_reclaim   # 开启，ratio=30
cat /sys/fs/cgroup/<cg>/memory.zram_reclaim
echo "0 0" > /sys/fs/cgroup/<cg>/memory.zram_reclaim    # 关闭
```
- 默认 ratio 30，范围 1-60；改 ratio 前必须先关闭（否则 `-EBUSY`）（`mm/Kconfig:74-80`）

### 管控逻辑
`zram_reclaim_should_use_policy`（`mm/zram_reclaim.c:205-280`）逐层 gate：
1. 无 memcg 或 `zram_file_weight_default == 0` → 不用；
2. `lru_gen_enabled()` → 不用（MGLRU 优先）；
3. memcg 未开启策略 → 不用；
4. 非 kswapd 且 `priority < ZRAM_PRIORITY_FLOOR`（接近 OOM 的直接回收）→ 交给 VM 正常路径；
5. anon 页少于 file 页一半 → 不用（缓存型负载不强行压匿名）；
6. `limit_ratio` 非 0 时：`swap_usage / (swap + anon) > limit%` → 不用；
7. 比较 anon/file 的「换入成本」估计（衰减计数，`mm/zram_reclaim.c:117-190`）：
   - 未被压垮 → 返回 true，回收器偏向匿名页；
   - 被压垮 → 把 swappiness 改成 `ZRAM_OVERLOAD_SWAPPINESS`，返回 false。
- 调用点：`get_scan_count`（`mm/vmscan.c:2452`）决定扫描比例；换入时记账在 `mm/memory.c:4478`。

### 判据
- `cat /sys/fs/cgroup/<cg>/memory.zram_reclaim`
- `memory.stat` 中 anon/file 回收比例变化
- `/proc/vmstat` 的 `pswpin`/`pswpout`

### 互斥与坑
- 只 ARM64 + 特定 CPU，x86 上这个文件根本不存在；不要写成「通用 zram 优化」。
- 与 MGLRU 互斥（见 §2）。

## 10. THP / mTHP

### 开启前置
- `CONFIG_TRANSPARENT_HUGEPAGE=y`、`CONFIG_TRANSPARENT_HUGEPAGE_ALWAYS=y`（x86-dc:1186-1187）

### 开关与参数
```bash
cat /sys/kernel/mm/transparent_hugepage/enabled   # [always] madvise never
cat /sys/kernel/mm/transparent_hugepage/defrag
ls /sys/kernel/mm/transparent_hugepage/hugepages-*/enabled
echo always > /sys/kernel/mm/transparent_hugepage/hugepages-64kB/enabled
```
- 全局属性：`enabled`（`mm/huge_memory.c:347`）、`defrag`（`:436`）、`use_zero_page`（`:450`）
- per-size 目录：`hugepages-<size>kB`（`mm/huge_memory.c:900`），anon 开关在 `mm/huge_memory.c:674-690`
- 默认：PMD order（2MB）为 `inherit`（`mm/huge_memory.c:956-960`），其余 size 默认 `never`

### 管控逻辑
1. **fault 分配**：缺页时 `thp_vma_allowable_orders` 判断该 vma 是否允许某 order 的大页，允许则尝试分配；失败回退小页。
2. **khugepaged**：后台扫描可合并的 vma，把 4K 页合并成大页（受 `defrag` 与 `khugepaged/*` 参数控制）。
3. **回收/换出**：大页在回收时按 order 拆分；`thp_swpout` 统计换出大页数，`thp_swpout_fallback` 是拆分回退。
4. **mTHP**：按 size 的 `enabled` 控制 fault 时是否允许该 order；`file_enabled`/`thp_exec_enabled` 控制文件/可执行映射。

### 判据
- `/proc/vmstat` 的 `thp_fault_alloc`、`thp_swpout`、`thp_swpout_fallback`、`thp_split_page`
- `/proc/meminfo` 的 `AnonHugePages`、`ShmemPmdMapped`

### 互斥与坑
- `defrag=always` 会增加分配时延；高碎片机器上可能频繁 compact。
- 大页换出会拆分，zram/zswap 的压缩收益变差。

## 11. zram（压缩内存盘 + 回写）

### 开启前置
- `CONFIG_ZRAM=m`（x86-dc:2412）；`CONFIG_ZRAM_WRITEBACK=y`、`CONFIG_ZRAM_MEMORY_TRACKING` 未设（x86-dc:2418-2419）
- `CONFIG_ZRAM_MEMORY_TRACKING=n` → `idle <秒>` 不可用，只能 `idle=all`（`drivers/block/zram/zram_drv.c:306-340`）

### 开关与参数（顺序敏感）
```bash
modprobe zram num_devices=1
echo /dev/ram0 > /sys/block/zram0/backing_dev   # 必须在 disksize 前
echo lz4 > /sys/block/zram0/comp_algorithm      # 也必须在 disksize 前
echo 512M > /sys/block/zram0/disksize
mkswap /dev/zram0 && swapon -p 100 /dev/zram0
echo 256M > /sys/block/zram0/mem_limit          # 限制 zram 自身内存
echo all > /sys/block/zram0/idle
echo idle > /sys/block/zram0/writeback
```
- 属性表：`drivers/block/zram/zram_drv.c:2159-2176`（disksize、mem_limit、idle、backing_dev、writeback、writeback_limit、recomp_*）
- `backing_dev_store` 的 `EBUSY` 检查在 `drivers/block/zram/zram_drv.c:460-490`

### 管控逻辑
1. **写路径**：`zram_bvec_write` 压缩页；内容相同的页标 `ZRAM_SAME`（不压缩，只记 same 计数）；超过 `mem_limit` 拒绝新页。
2. **读路径**：`zram_bvec_read` 解压；命中 SAME 页直接重建。
3. **idle 标记**：`idle_store`（`drivers/block/zram/zram_drv.c:306-340`）把已分配 slot 标 `ZRAM_IDLE`；`all` = 全标；关 MEMORY_TRACKING 时秒数参数不可用。
4. **回写**：`writeback_store`（`drivers/block/zram/zram_drv.c:600-640`）支持模式：`idle`、`huge`、`huge_idle`、`incompressible`，以及 `page_index`（`PAGE_WB_SIG`）单页回写；每页一个 bio、`submit_bio_wait` 同步串行。
5. **回写量限制**：`writeback_limit`/`writeback_limit_enable` 限制一次回写 IO 量。
6. **统计**：`mm_stat`（orig/comp/mem_used）、`bd_stat`（回写页数，单位 4K bytes，`drivers/block/zram/zram_drv.c:1191-1203`）。

### 判据
- `cat /sys/block/zram0/mm_stat`、`cat /sys/block/zram0/bd_stat`
- `zramctl`、`swapon --show`

### 互斥与坑
- `backing_dev`/`comp_algorithm` 顺序错 → `EBUSY`；
- 回写跳过 `ZRAM_SAME` 页（文本数据要让每页唯一 salt，否则 `bd_count` 恒 0）；
- 回写是同步串行，100MiB 回写成本高，别当后台异步。

## 12. memcg QoS（openEuler 扩展）

### 开启前置
- `CONFIG_MEMCG_QOS`（x86-dc:191）、`CONFIG_MEMCG_OOM_PRIORITY`（x86-dc:193）、`CONFIG_MEMCG_SWAP_QOS`（x86-dc:194）

### 开关与参数
```bash
cat /proc/sys/kernel/memcg_qos_enable           # 默认 0
echo 1 > /proc/sys/kernel/memcg_qos_enable     # 开 OOM 优先级
cat /proc/sys/kernel/memcg_swap_qos_enable     # 默认 0
cat /sys/fs/cgroup/<cg>/memory.qos_level       # 0/1（低/高 OOM 优先级）
cat /sys/fs/cgroup/<cg>/memory.high_async_ratio
cat /sys/fs/cgroup/<cg>/memory.force_swapin    # 写触发
cat /sys/fs/cgroup/<cg>/memory.swapfile        # 绑 swap 设备
```
- OOM 优先级默认值：`sysctl_memcg_oom_prio = 0`（`mm/memcontrol.c:4369`）；读写在 `mm/memcontrol.c:4388-4420`；cgroup 文件 `qos_level`（`mm/memcontrol.c:6340-6349`）
- swap QoS 默认 0（`mm/memcontrol.c:4550`）；接口 `force_swapin`/`swapfile`/`swap.max` 在 `mm/memcontrol.c:6455-6485`

### 管控逻辑
1. **OOM 优先级**：开 sysctl 后，`memory.qos_level` 0/1 决定该 memcg 在全局 OOM 中的先后；子 cgroup 初始化时继承父（`mm/memcontrol.c:4376-4390`）；OOM 选择时按优先级调整候选顺序（`mm/memcontrol.c:4438`、`mm/memcontrol.c:4506`）。
2. **high_async_ratio**：`memory.high` 触发异步回收时，按 ratio 计算提前预警水位（`mm/memcontrol.c:120-124`），`async_reclaim_high`（`mm/memcontrol.c:2599-2618`）在未超限时也提前回收。
3. **swap QoS**：`force_swapin` 扫描 memcg 内任务强制换入（`mm/memcontrol.c:4636-4644`）；`swapfile` 给 memcg 绑定 swap 设备；`swap.max` 是带 QoS 统计的 swap 限额。

### 判据
- sysctl 值 + cgroup 文件存在性；
- `memory.events` 的 `oom` 计数分布。

### 互斥与坑
- sysctl 默认 0 时，`memory.qos_level` 读恒为 0、写返回 `-EACCES`（`mm/memcontrol.c:4391-4394`）——不先开 sysctl 就调 cgroup 文件会「看起来没生效」。
- 这是 openEuler 扩展，上游 6.6 没有；不要按上游文档写。

## 13. compaction（附）

### 开启与参数
- `CONFIG_COMPACTION=y`（x86-dc:1167）；proactiveness 默认 20（`mm/compaction.c:1919`）
- `echo 1 > /proc/sys/vm/compact_memory` 手动触发；`kcompactd` 后台整理

### 管控逻辑
1. 分配高阶页失败 → 慢路径先 direct compaction（`mm/compaction.c:2255-2263` 按 watermarks 与 proactiveness 决定是否做）；
2. `kcompactd` 在空闲时按 proactiveness 比例后台整理；
3. 判据：`/proc/vmstat` 的 `compact_*`（stall、success、fail）。

### 坑
- proactiveness 越高越积极，但 CPU 与延迟上升；SSD/大内存机器可适当提高，延迟敏感场景降低。

## 14. 组合与互斥矩阵

| 组合 | 关系 | 说明 |
|---|---|---|
| MGLRU × zram_reclaim | **互斥** | MGLRU 生效时 zram_reclaim 直接不介入（`mm/zram_reclaim.c:209-211`） |
| zswap × zram | 可叠加但重复压缩 | zswap 在前、zram 在后，CPU 翻倍 |
| DAMON_LRU_SORT × MGLRU | 冲突风险 | 两者都改 LRU 行为 |
| NUMA balancing(tiering) × demotion | 互补 | tiering 管 promote，demotion 管下沉 |
| etmem × zram_reclaim | 目标重叠 | 都偏向匿名页回收，叠加会放大 swap |
| PSI × 任意 | 观测层 | 不改变回收行为，只提供信号 |

**沙箱/容器场景推荐**：MGLRU 或 zram_reclaim 二选一（ARM64 海思选后者）；zram 作 swap 设备时 zswap 关；有 CXL/PMEM 分层时开 demotion + `numa_balancing=2`；PSI 常开做反馈；memcg `memory.high` 作为租户节流。

## 15. 验证清单（最短路径）

```bash
# 1) 配置
zcat /proc/config.gz | grep -E 'CONFIG_(LRU_GEN|ZSWAP|ZRAM|DAMON|ETMEM|PSI|MEMCG)'

# 2) 运行时
cat /proc/sys/kernel/numa_balancing
cat /sys/kernel/mm/lru_gen/enabled
cat /sys/module/zswap/parameters/enabled
cat /sys/kernel/mm/numa/demotion_enabled
cat /proc/pressure/memory 2>/dev/null || echo "PSI off"
cat /sys/kernel/mm/swap/kernel_swap_enable

# 3) 设备/接口
zramctl; swapon --show; ls /sys/fs/cgroup/<cg>/memory.zram_reclaim 2>/dev/null

# 4) 计数器
grep -E 'pgscan|pgsteal|pswpin|pswpout|pgdemote_|thp_|numa_|compact_|zswap_' /proc/vmstat
```

**判定原则**：能读到开关 + 计数器有增量，才算「打开并生效」；只有 Kconfig 或只有 sysfs 文件存在都不算。
