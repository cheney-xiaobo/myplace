## 1. 全景：内存管理在管什么

Linux 内存管理要同时解决四个层面的问题，代码也按这四层划分：

| 层次 | 要解决的问题 | 主要代码 | 关键对象 |
| --- | --- | --- | --- |
| ① 物理内存建模 | 机器有多少内存、分成哪些节点/区域、每页什么状态 | `include/linux/mmzone.h`、`mm/sparse.c`、`mm/memblock.c` | `pg_data_t`、`zone`、`struct page`、`folio` |
| ② 物理页分配 | 谁要一页、从哪个区域、什么迁移类型 | `mm/page_alloc.c` | buddy、PCP、watermark、gfp flags |
| ③ 内核对象分配 | 内核自己用的比页更小的对象 | `mm/slub.c`、`mm/vmalloc.c` | `kmem_cache`、`vm_struct` |
| ④ 进程地址空间 | 每个进程看到的一大片虚拟地址 | `mm/mmap.c`、`mm/memory.c`、`mm/rmap.c` | `mm_struct`、`vm_area_struct`、页表 |
| ⑤ 回收与配额 | 内存不够时收回谁、谁被限制 | `mm/vmscan.c`、`mm/memcontrol.c`、`mm/oom_kill.c` | `lruvec`、`mem_cgroup`、OOM |

一条主线可以概括成：

```
物理内存在启动期由 memblock 收集
   → 交给 buddy 分配器按 zone/迁移类型管理
   → 内核小对象用 slub 从 buddy 切块
   → 进程访问虚拟地址时缺页，从 buddy 要页并建立页表映射
   → 内存紧张时，kswapd/直接回收 按 LRU 挑页，干净页直接丢、脏页先回写、匿名页写入 swap
   → 容器场景再叠加 memcg 的独立配额与回收
```

## 2. 物理内存的表示：节点、区域、页

### 2.1 三级结构：node → zone → page

```c
/* include/linux/mmzone.h:1328 */
typedef struct pglist_data {
	...
	struct zone node_zones[MAX_NR_ZONES];      /* :1334 本节点的区域 */
	struct zonelist node_zonelists[MAX_ZONELISTS]; /* :1341 分配时的区域回退顺序 */
	...
	unsigned long node_start_pfn;       /* :1365 起始物理页号 */
	unsigned long node_present_pages;   /* :1366 实际存在的页数 */
	unsigned long node_spanned_pages;   /* :1367 含空洞的跨度 */
	...
	struct task_struct *kswapd;         /* :1382 本节点的回收线程 */
} pg_data_t;                                /* :1472 */
```

- **node**（NUMA 节点）：非 NUMA 机器只有一个 `node 0`。`node_zonelists` 决定「本节点分配失败后去哪些节点试」。
- **zone**：同一节点内按「可寻址范围」再切。枚举在 `include/linux/mmzone.h:767`，顺序是 `ZONE_DMA` → `ZONE_DMA32` → `ZONE_NORMAL` → `ZONE_HIGHMEM`（32 位专有）→ `ZONE_EXTMEM`（本树 openEuler 增量）→ `ZONE_MOVABLE`。
  - `ZONE_DMA`/`ZONE_DMA32`：给寻址能力受限的设备用。
  - `ZONE_NORMAL`：普通内核可寻址内存。
  - `ZONE_MOVABLE`：只放可迁移页，为内存热插拔/大页腾挪服务（`include/linux/mmzone.h:804-852` 的长注释列了 pin、memblock、hwpoison、hotplug 等 7 类例外）。
- **page / folio**：最小管理单位。x86_64 上 `struct page` 是 64 字节（`CONFIG_MEMCG` 与部分配置会影响大小，未逐配置验证），`struct folio` 是「一个或多个物理连续页」的头部表示。

### 2.2 `struct zone` 里真正重要的字段

```c
/* include/linux/mmzone.h:865 */
struct zone {
	...
	unsigned long _watermark[NR_WMARK];   /* :869 三条水位线 */
	unsigned long watermark_boost;        /* :870 临时抬高水位的补偿 */
	...
	struct per_cpu_pages __percpu *per_cpu_pageset; /* :889 每 CPU 页缓存 */
	...
	unsigned long zone_start_pfn;         /* :908 */
	/* :915-926 三个计数的关系：
	   spanned_pages = zone_end_pfn - zone_start_pfn      （含空洞）
	   present_pages = spanned_pages - absent_pages       （扣物理空洞）
	   managed_pages = present_pages - reserved_pages     （buddy 真正管的部分） */
```

水位线是关键机制，`enum zone_watermarks`（`include/linux/mmzone.h:677-683`）定义了 `WMARK_MIN / LOW / HIGH / PROMO`，取值宏在 `:703-706`：

```c
#define min_wmark_pages(z)  (z->_watermark[WMARK_MIN]  + z->watermark_boost)
#define low_wmark_pages(z)  (z->_watermark[WMARK_LOW]  + z->watermark_boost)
#define high_wmark_pages(z) (z->_watermark[WMARK_HIGH] + z->watermark_boost)
```

含义：
- 低于 **MIN**：只有带 `__GFP_HIGH`/`PF_MEMALLOC` 的分配（回收路径自己要用内存）才放行。
- 低于 **LOW**：唤醒 `kswapd` 异步回收。
- 高于 **HIGH**：`kswapd` 可以睡了。
- **PROMO**：比 HIGH 更高的一档，只在开启 NUMA 内存分层（`NUMA_BALANCING_MEMORY_TIERING`）时启用——kswapd 以它为回收目标、`zone_balanced()` 以它判定是否够用（`mm/vmscan.c:6707-6711`、`:4793-4794`），目的是给「热点页提升到快层」预留余量。默认配置下不生效。

### 2.3 页的描述符与引用计数

```c
/* include/linux/mm_types.h:77 */
struct page {
	...
	struct address_space *mapping;   /* :109 映射到哪个 address_space（page cache 用） */
	...
	atomic_t _mapcount;              /* :172 被多少个页表项映射 */
	...
	atomic_t _refcount;              /* :184 引用计数 */
```

```c
/* include/linux/mm_types.h:323 */
struct folio {
	union {
		struct {
			...
			struct address_space *mapping;  /* :340 */
			...
			atomic_t _mapcount;             /* :346 */
			atomic_t _refcount;             /* :347 */
```

两个计数要分清：
- `_refcount`：有多少人「持有」这一页（页表映射、page cache、bio、临时 pin）。归零才可释放。
- `_mapcount`：这一页被多少**用户页表项**映射。回收时用它判断是否还能「就地摘除」——大于 0 说明还有别人映射着，需要走 rmap 反查。

### 2.4 稀疏内存模型

大机器上物理内存不连续，`CONFIG_SPARSEMEM_VMEMMAP=y`（`openeuler_defconfig:1148`）把 `struct page` 数组做成虚拟连续映射，用 `mem_section` 描述不连续区段：

```c
/* include/linux/mmzone.h:1882 */
struct mem_section {
	/* 逻辑上是指向 struct page 数组的指针，但编码了 node id 等标志位，
	   见 sparse.c::sparse_init_one_section()。 */
```

这带来一个重要结论：**`pfn_to_page()` 是算术运算**（虚拟地址空间里 `vmemmap` 连续），但「这段 pfn 是否真的存在」要靠 section 的 present 位判断。

### 2.5 迁移类型：碎片控制的核心

```c
/* include/linux/mmzone.h:50 */
enum migratetype {
	MIGRATE_UNMOVABLE,   /* 内核数据结构，不能搬 */
	MIGRATE_MOVABLE,     /* 用户页、page cache，可迁移 */
	MIGRATE_RECLAIMABLE, /* 可回收的 slab */
	MIGRATE_PCPTYPES,
	MIGRATE_HIGHATOMIC = MIGRATE_PCPTYPES, /* 应急保留区，防 GFP_ATOMIC 失败 */
	...
	MIGRATE_CMA,         /* 连续内存分配器专用 */
	MIGRATE_ISOLATE,     /* 被隔离，不参与分配 */
};
```

buddy 的空闲链表按迁移类型分开（`include/linux/mmzone.h:119-122`）：

```c
struct free_area {
	struct list_head free_list[MIGRATE_TYPES];
	unsigned long    nr_free;
};
```

**设计意图**：把「能搬的」和「不能搬的」分开放，长期运行后仍能凑出大块连续内存（THP、大块 DMA）。申请时若目标类型没有，会按 fallback 表降级：`fallbacks[MIGRATE_TYPES][MIGRATE_PCPTYPES-1]`（`mm/page_alloc.c:1651`）。

## 3. 启动期：`memblock` 先接手

内核刚启动时 buddy 还不能用（它自己需要内存来建结构），所以先由 `memblock` 管理物理内存：

- `memblock_add_range()`（`mm/memblock.c:595`）：注册一段可用物理内存；
- `memblock_reserve()`（`:913`）：把已被占用（内核映像、设备树、initrd）的区间标记为保留；
- 早期分配用 `memblock_phys_alloc_range()`（`:1554`）/ `memblock_alloc_try_nid_raw()`（`:1698`）。

启动后期 `mm_init()` 把 memblock 里剩下的内存交给 buddy，之后 memblock 主要只保留「保留区」记录。所以在运行时观察到的 `MemTotal` 已经是「物理内存 − 内核保留 − 空洞」，与 memblock 的 memory 区段不是一回事。

## 4. 页分配器：buddy + PCP

### 4.1 唯一的分配入口

所有物理页分配最终都走这里：

```c
/* mm/page_alloc.c:4998 */
struct page *__alloc_pages(gfp_t gfp, unsigned int order, int preferred_nid,
							nodemask_t *nodemask)
```

快路径在 `get_page_from_freelist()`（`mm/page_alloc.c:3409`）里，按 zonelist 顺序逐个 zone 尝试：
1. **PCP**（per-CPU pageset）：单页分配命中每 CPU 的缓存链表，不加 zone 锁；
2. **buddy**：`rmqueue_pcplist()`（`mm/page_alloc.c:3087`）/ `__rmqueue()`（`:2279`）；
3. **水位检查**：`__zone_watermark_ok()`（`:3196`）；
4. 失败则进慢路径 `__alloc_pages_slowpath()`（`:4367`）。

```c
/* include/linux/mmzone.h:723 */
struct per_cpu_pages {
	...
};
```

PCP 的意义：单页分配是最高频操作，如果每次都抢 `zone->lock`，多核会直接退化。PCP 让每 CPU 批量从 buddy 取一批页放在本地，分配/释放都先走本地链表。

### 4.2 gfp flags：一次分配的全部约束

gfp 的位定义在 `include/linux/gfp_types.h`。常用的语义：

| 标志 | 含义 | 典型场景 |
| --- | --- | --- |
| `__GFP_DIRECT_RECLAIM` | 允许自己触发直接回收 | 普通进程上下文分配 |
| `__GFP_KSWAPD_RECLAIM` | 允许唤醒 kswapd | 几乎所有可睡眠分配 |
| `__GFP_IO` / `__GFP_FS` | 允许做 IO / 调用文件系统 | 回收脏页时需要；`__GFP_NOFS` 会禁止 |
| `__GFP_ATOMIC` | 不可睡眠（隐含不允许回收/IO） | 中断、持锁路径 |
| `__GFP_ZERO` | 返回前清零 | 安全敏感分配 |
| `__GFP_MOVABLE` | 允许从可迁移区域分配 | 用户页、page cache |
| `__GFP_HIGH` | 可动用应急保留 | 回收路径自身 |
| `__GFP_NORETRY` / `__GFP_RETRY_MAYFAIL` | 控制重试力度 | 大页分配、避免 OOM |

慢路径的判断直接依赖这些位：

```c
/* mm/page_alloc.c:4367-4370（节选） */
__alloc_pages_slowpath(gfp_t gfp_mask, unsigned int order, ...)
{
	bool can_direct_reclaim = gfp_mask & __GFP_DIRECT_RECLAIM;
```

关键点：**`can_direct_reclaim` 为假时根本不会走回收**（`:4542`、`:4550`），这正是「原子上下文分配失败只能返回 NULL」的代码依据。page cache 的 `mapping_gfp_mask` 默认是 `GFP_HIGHUSER_MOVABLE`（`fs/inode.c:211`），即「可睡眠、可 IO、可迁移」。

### 4.3 直接回收与水位

```c
/* mm/page_alloc.c:4030 */
__alloc_pages_direct_reclaim(gfp_t gfp_mask, unsigned int order, ...)
```

慢路径的顺序大致是：唤醒 kswapd → 等待 → 自己直接回收 → 内存压缩（compaction）→ 重试 → 最后才 OOM。`__zone_watermark_ok()`（`:3196`）负责判断「这个 zone 现在还够不够格分配」。

水位参数：

```c
/* mm/page_alloc.c:306,309 */
int min_free_kbytes = 1024;              /* 默认值，实际按内存大小算 */
static int watermark_scale_factor = 10;  /* 每 zone 额外预留的比例（万分之 10） */
```

实际值由 `calculate_min_free_kbytes()`（`:6437`）按 `sqrt(lowmem_kbytes*16)` 计算并 clamp 到 128 KB ~ 256 MB（`:6446`）。16 GB 机器约 16 MB——这个数字同时也是 dirtyable memory 公式里 `totalreserve_pages` 的主要成分（见 page cache 专文 §8.3.1）。

### 4.4 碎片与整理

- **compaction**（`CONFIG_COMPACTION=y`，`openeuler_defconfig:1167`）：把可迁移页搬到一起，腾出连续块。实现 `mm/compaction.c`。
- **CMA**（`CONFIG_CMA=y`，`:1199`）：给摄像头/GPU 这类需要大块连续物理内存的设备预留区域，空闲时可被可迁移分配临时借用。实现 `mm/cma.c`。
- **迁移**：`migrate_pages()`（`mm/migrate.c:2025`）是所有「搬页」操作的公共入口（compaction、NUMA balance、memory hotremove、MGLRU 的 promote 都调它）。

## 5. slab / slub：内核小对象

buddy 最小单位是一页（4 KB），但内核大量对象只有几十到几百字节，于是有了 slab 分配器。本树用 SLUB：

```
openeuler_defconfig:1134  CONFIG_SLUB=y
```

入口：

```c
/* mm/slub.c:3525 */
void *kmem_cache_alloc(struct kmem_cache *s, gfp_t gfpflags)
/* mm/slub.c:3546 */
void *kmem_cache_alloc_node(struct kmem_cache *s, gfp_t gfpflags, int node)
```

- `struct kmem_cache`：一类对象的「模具」，记录对象大小、对齐、构造/析构函数；
- SLUB 用一个或多个页组成 slab，页内切成固定大小对象，用 freelist 串联；
- 每个 `kmem_cache` 有 per-CPU 缓存（`cpu_slab`），分配优先命中本地；
- `kmalloc()` 系列则从预定义的 size class 缓存里取。

观察点：`/proc/slabinfo`、`/sys/kernel/slab/*/`。`MemAvailable` 里会算「可回收 slab」（`NR_SLAB_RECLAIMABLE_B`，`fs/proc/meminfo.c:59`）。

## 6. vmalloc：要连续虚拟地址，不要连续物理地址

```c
/* mm/vmalloc.c:3802 */
void *__vmalloc_node_range(unsigned long size, unsigned long align,
/* mm/vmalloc.c:3987 */
void *vmalloc(unsigned long size)
```

用途：模块加载、大块 `kvmalloc` 回退、ioremap 等。内核在 vmalloc 区域（x86_64 上是一段专门的虚拟地址区间）里找空洞，再逐页分配物理页并建立页表。

**与 buddy 的取舍**：vmalloc 得到的虚拟地址连续、物理地址不连续，TLB 压力大、需要建页表，所以高频小对象一律走 slab，不要用 vmalloc。

## 7. 进程地址空间：`mm_struct` + VMA + 页表

### 7.1 两个核心结构

```c
/* include/linux/mm_types.h:760 */
struct mm_struct {
	...
	atomic_t mm_count;              /* :774 结构体本身引用数 */
	unsigned long mmap_base;        /* :783 mmap 区域起点 */
	unsigned long task_size;        /* :790 用户空间大小 */
	pgd_t *pgd;                     /* :791 顶层页表 */
```

```c
/* include/linux/mm_types.h:642 */
struct vm_area_struct {
	unsigned long vm_start;    /* :648 区间起点 */
	unsigned long vm_end;      /* :649 区间终点 */
	struct mm_struct *vm_mm;   /* :656 属于哪个地址空间 */
	pgprot_t vm_page_prot;     /* :657 页表权限 */
	const vm_flags_t vm_flags; /* :665 读写执行/共享私有等 */
	struct list_head anon_vma_chain; /* :706 反向映射链 */
	const struct vm_operations_struct *vm_ops; /* :711 文件/设备操作 */
	unsigned long vm_pgoff;    /* :714 在文件内的偏移（以页为单位） */
	struct file *vm_file;      /* :716 映射的文件，匿名映射为 NULL */
```

一个进程的地址空间 = 一棵 VMA 树（红黑树）+ 一张页表 + 一组统计。VMA 是「连续同属性」的区间，不是每一页一个结构——这点是理解 `mmap` 性能的关键。

### 7.2 建立映射

```c
/* mm/mmap.c:1498 */
unsigned long do_mmap(struct file *file, unsigned long addr, ...)
/* mm/mmap.c:3092 */
unsigned long mmap_region(struct file *file, unsigned long addr, ...)
```

`mmap()` 系统调用 → `do_mmap()` → `mmap_region()`：找到空洞、创建 VMA、插入红黑树、必要时合并相邻 VMA。**此时并没有分配物理页**，只是登记意向——真正的物理页在第一次访问触发缺页时才分配（这就是「延迟分配」在地址空间层的体现）。

### 7.3 页表级数

x86_64 本树配置 `CONFIG_X86_5LEVEL=y`（`openeuler_defconfig:466`），因此 `CONFIG_PGTABLE_LEVELS` 默认 5：

```c
/* arch/x86/Kconfig:410-414 */
config PGTABLE_LEVELS
	int
	default 5 if X86_5LEVEL
	default 4 if X86_64
	default 3 if X86_PAE
```

5 级页表（PGD→P4D→PUD→PMD→PTE）让用户虚拟地址上限从 47 位扩到 56 位，但**只有进程显式请求高地址时**才用第五级，否则内核把 P4D 折叠，行为与 4 级一致（`include/linux/pgtable.h:21-22` 的编译期一致性检查）。

### 7.4 锁：mmap_lock 与 per-VMA lock

传统上 VMA 树由 `mmap_lock`（读写信号量）保护。本树有 per-VMA 锁优化：

```c
/* mm/memory.c:6290 */
struct vm_area_struct *lock_vma_under_rcu(struct mm_struct *mm,
```

缺页时先在 RCU 读侧找到 VMA 并尝试 `vma_start_read()`（`:6302`），成功就不必取 `mmap_lock`——这显著降低了多线程缺页的争用。

## 8. 缺页：物理页真正诞生的地方

```c
/* mm/memory.c:6114 */
vm_fault_t handle_mm_fault(struct vm_area_struct *vma, unsigned long address,
```

这是缺页的总入口，按 VMA 类型分派：

| 场景 | 处理函数 | 行号 | 行为 |
| --- | --- | --- | --- |
| 匿名页首次访问 | `do_anonymous_page()` | `mm/memory.c:4799` | 分配零页或新页，建 PTE |
| 文件页缓存未命中 | `do_fault()` | `:5475` | 回调 `vm_ops->fault`，进 page cache 读路径 |

## 9. 回收：内存不够时收谁

### 9.1 LRU 双链结构

```c
/* include/linux/mmzone.h:275 */
enum lru_list {
	LRU_INACTIVE_ANON, LRU_ACTIVE_ANON,
	LRU_INACTIVE_FILE, LRU_ACTIVE_FILE,
	LRU_UNEVICTABLE,
	NR_LRU_LISTS
};

/* include/linux/mmzone.h:637 */
struct lruvec {
	...
};
```

每个 `lruvec`（按 node/zone 与 memcg 组合）维护这 5 条链。**file LRU 同时容纳 page cache 和 shmem；anon LRU 是可换出的匿名页；unevictable 是被 mlock 等钉住、永不回收的页。**

### 9.2 三条回收路径

| 路径 | 触发 | 入口 | 特点 |
| --- | --- | --- | --- |
| kswapd 异步 | 水位低于 LOW | `kswapd()`（`mm/vmscan.c:7193`）→ `balance_pgdat()`（`:6864`） | 后台线程，不阻塞申请者 |
| 直接回收 | 水位低于 MIN 且允许 `__GFP_DIRECT_RECLAIM` | `__alloc_pages_direct_reclaim()`（`mm/page_alloc.c:4030`） | 申请者自己回收，延迟高 |
| memcg 回收 | cgroup 超限 | `mm/memcontrol.c` 的 charge 路径 | 只收本 cgroup |

唤醒入口：

```c
/* mm/vmscan.c:7279 */
void wakeup_kswapd(struct zone *zone, gfp_t gfp_flags, int order,
```

公共主干：

```c
/* mm/vmscan.c:5968 */
static void shrink_node(pg_data_t *pgdat, struct scan_control *sc)
```

`shrink_node()` 里做几件事：算各 LRU 该扫多少（`get_scan_count()`）、`shrink_list()` 分流 active/inactive、`shrink_inactive_list()` 逐个 `shrink_folio_list()`。单页回收的全部判断都在 `shrink_folio_list()`（`mm/vmscan.c:1035`）里，细节见 page cache 专文 §4.6。

### 9.3 匿名页与 swappiness

```c
/* mm/vmscan.c:203 */
int vm_swappiness = 60;
```

`swappiness` 决定「anon 与 file 的扫描比例」。它是相对权重不是绝对开关：即使设为 0，匿名页在极端压力下仍可能被换出（代码里用的是 `anon_cost`/`file_cost` 加权，见 `get_scan_count()`）。**对 page cache 型负载（数据库、静态文件服务），调低 swappiness 能把内存更多留给缓存。**

### 9.4 MGLRU（本树默认关闭）

`CONFIG_LRU_GEN=y`（`openeuler_defconfig:1235`）但 `LRU_GEN_ENABLED` 未开。MGLRU 用「分代 + 每代多队列」替代 active/inactive 二分，扫描时先扫老代，且用 `max_seq` 判断页的年龄，减少了二次机会链的抖动。开启方式：`echo y > /sys/kernel/mm/lru_gen/enabled`（`mm/vmscan.c:5220` 附近）。

### 9.5 回收与回写的耦合

回收器自己不等 IO：遇到脏页就发起 `WB_SYNC_NONE` 回写然后放回（`pageout()`，`mm/vmscan.c:626`），并在写回中打 `PG_reclaim` 计数；扫到大量未入队脏页时主动唤醒 flusher（`:2018`）。所以**「回收慢」通常不是回收算法慢，而是回写带宽不够**——这正是 page cache 专文 §4.7 那条控制环存在的原因。

## 10. swap、zswap、zram

### 10.1 swap 的三种后端

| 方案 | 位置 | 代价 |

### 10.2 swap 的核心结构

## 11. 与 page cache 的衔接

page cache 是「文件内容在内存里的副本」，挂在 `address_space->i_pages`（XArray）上，用 folio 表示。它的分配、回收、回写完全复用本文的机制：

- 分配：`filemap_add_folio()` → `filemap_alloc_folio()` → `alloc_pages()`（§4）；
- 回收：folio 挂在 file LRU 上，由 §9 的路径回收；
- 脏页限流：§9.5 的回写反馈环；
- 大 folio：file mTHP（本树默认标志位里已包含 `TRANSPARENT_HUGEPAGE_FILE_MTHP_FLAG`，`mm/huge_memory.c:72`），但需要文件系统在 `address_space` 上 opt-in（`mapping_set_large_folios`）——XFS 默认开，ext4 默认不开。

细节全部在 [[Page Cache 分析]]。本节不再重复。

## 12. NUMA

- 配置：`CONFIG_NUMA_BALANCING=y`（`openeuler_defconfig:185`），且 **`CONFIG_NUMA_BALANCING_DEFAULT_ENABLED=y`**（`:186`），即开机就生效，不需要额外内核参数。
- 结构：每个 node 一组 zone（§2.1），`node_zonelists` 决定回退顺序。
- 自动平衡：内核周期性给任务「解映射」一部分页，让下次访问重新缺页时在**就近节点**分配，并迁移已有页。参数入口 `sysctl_numa_balancing_scan_period_min`（`kernel/sched/fair.c:1779`）等，实现在 `task_numa_fault()` 一族（同一文件）。
- 迁移：`migrate_pages()`（`mm/migrate.c:2025`）。
- 手工策略：`mbind()`/`set_mempolicy()` → `mm/mempolicy.c`。
- 观察：`/sys/devices/system/node/node*/numastat`、`numactl --hardware`。

**代价**：numa balancing 会增加缺页与迁移开销，延迟敏感负载通常建议关掉（`numa_balancing=disable`）。

## 13. memcg 与 OOM

### 13.1 计费

```c
/* include/linux/memcontrol.h:259 */
struct mem_cgroup {
```
```c
/* mm/memcontrol.c:2871 */
static int try_charge_memcg(struct mem_cgroup *memcg, gfp_t gfp_mask,
/* mm/memcontrol.c:8435 */
int __mem_cgroup_charge(struct folio *folio, struct mm_struct *mm, gfp_t gfp)
```

- 页第一次被某个 cgroup 触达时 charge（`__mem_cgroup_charge`），之后迁移/复用要处理「换 charge」；
- 超限时先尝试回收本 cgroup 的 LRU（memcg 有自己的 `lruvec`，就是 §9.1 那个结构按 memcg 再分一层）；
- 回收不动才 OOM。

配置：`CONFIG_MEMCG=y`（`openeuler_defconfig:190`）。

**注意**：page cache 也计入 memcg。一个容器读大量文件会把 page cache 记到自己账上，超限时同样触发回收——这是容器里「缓存看起来总是很小」的常见原因。

### 13.2 OOM

```c
/* mm/oom_kill.c:1244 */
bool out_of_memory(struct oom_control *oc)
```

选择依据是 `oom_badness()`（同文件，按 `oom_score_adj` 与内存占用加权）。触发条件按顺序：
1. 直接回收 + compaction 都失败；
2. 且 `gfp_mask` 允许（不是 `__GFP_NORETRY` 之类）；
3. memcg 限流场景下只杀本 cgroup 内的任务。

`panic_on_oom`、`oom_kill_allocating_task` 等 sysctl 改变行为。

## 14. 大页、KSM、整理

### 14.1 THP


- 匿名 THP：缺页时直接给 2 MB（`do_huge_pmd_anonymous_page()`，`:1539`）；

### 14.2 KSM（同页合并）


对 `MADV_MERGEABLE` 的匿名页做内容哈希，相同内容合并为一页（写时复制）。省内存、费 CPU，适合虚拟机/容器镜像这类大量重复页的场景。`CONFIG_KSM=y`（`openeuler_defconfig:1179`），但**必须显式 madvise 才生效**。

```c
/* mm/memory_hotplug.c:1409 */
```

## 19. 三条贯穿全局的线索

1. **延迟与惰性**：`mmap` 不分配页、`malloc` 不分配页、写文件不立即落盘、大页不立即合并。所有「先用再说」的设计都是为了把成本推到真正需要的那一刻，并用配额与回收兜住最坏情况。
2. **分级兜底**：分配有 PCP → buddy → 直接回收 → compaction → OOM 五级；回收有 kswapd → 直接回收 → memcg 回收；限流有 freerun → 软限 → 硬限。**每级都比上一级更贵或更痛**，所以「系统变慢」通常意味着已经掉到第二级以后。
3. **回收质量决定体验**：干净页可丢、脏页要先写、匿名页要写 swap。**内存压力的最终表现几乎总是 IO 压力**——这也是为什么要给 page cache 单独的脏页限流（见 page cache 专文 §4.7），否则回写会反过来拖垮整机。
